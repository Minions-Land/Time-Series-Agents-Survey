\textbf{Abstract.}
Time series research is moving from isolated prediction models toward agentic systems that inspect temporal data, retrieve context, call analytical tools, validate intermediate evidence, revise outputs, and support downstream decisions. This transition creates a conceptual gap for the community: existing surveys explain large language models for time series, time-series foundation models, or multimodal temporal reasoning, but they do not fully specify what makes an LLM-based system an agent for temporal analysis. This survey provides a harness-centric guide to that gap. It first clarifies the operational meaning of an Agent and a Time Series Agent, then identifies the Harness components that turn an LLM into a stateful, tool-using, verifiable system. Building on this vocabulary, we review what current Time Series Agents have implemented, which parts of the design are general-agent infrastructure, and which parts are time-series-domain modules. We further summarize design boundaries for building new systems, including temporal workspaces, typed tools, memory, workflow control, verification, multi-agent coordination, and capability evolution. Finally, we organize benchmarks and evaluation protocols so that future Time Series Agents can be compared not only by final predictive accuracy, but also by tool correctness, temporal faithfulness, context use, trace quality, and decision-oriented reliability.
\end{tcolorbox}

\section{Introduction}

Time series analysis has long been organized around task-specific predictors: forecasting, classification, anomaly detection, imputation, segmentation, and representation learning. This model-centric paradigm has produced a mature ecosystem spanning classical statistical methods, deep neural architectures, foundation models, and LLM-enhanced temporal models \citep{zhang2024llmts,jiang2024empowering}. These systems are essential, but most of them are designed to answer a bounded modeling question once the task, data split, features, context, and evaluation protocol have already been specified.

However, real temporal analysis rarely ends with a single model output. A practitioner must inspect data quality, verify temporal granularity, identify regime shifts, retrieve events, select tools, compare models, validate against chronological splits, explain evidence, revise forecasts under constraints, and turn predictions into operational decisions. These steps require a system-level runtime, not only a stronger backbone model.

LLM agents provide a natural system abstraction for this broader workflow. In the general agent literature, a harness surrounds an LLM with external computation, action schemas, tools, memory, state, execution loops, validators, observability, and permission boundaries \citep{li2026harnesssurvey,ning2026codeharness,lee2026metaharness}. A concise operational reading is therefore: an \keyterm{Agent is an LLM embedded in a general Harness}. The LLM supplies language understanding, planning, and judgment; the general Harness supplies the interface and control surfaces that make actions executable, stateful, auditable, and revisable.

Time series add a domain layer that a generic agent harness does not automatically provide. Temporal data require chronological causality, leakage control, frequency and unit semantics, temporal alignment, missingness handling, non-stationarity awareness, uncertainty treatment, and metric-verifiable numerical outputs. This motivates the central framing of the survey: a \keyterm{Time Series Agent is an LLM embedded in a general Harness plus a Time-series Harness Module}. The Time-series Harness Module is the part of the system that makes temporal objects native to the agent runtime rather than treating them as ordinary text.

\keyterm{Operational framing.} A general Agent couples an LLM with a \hcomp{general Harness}. A Time Series Agent keeps this general Harness and adds a \hcomp{Time-series Harness Module}: temporal workspace, typed time-series tools, temporal grounding of context, leakage-aware validation, temporal memory, and domain tool libraries.
\end{tcolorbox}

This framing separates two kinds of contribution that are often conflated. A paper may improve the \hcomp{general Harness}: planning, tool use, reflection, memory retrieval, tool synthesis, debate, control, or harness optimization. Or it may improve the \hcomp{Time-series Harness Module}: time-indexed workspaces, temporal tool schemas, context-series alignment, forecast revision constraints, temporal validation, domain memory, or time-series benchmark protocols. Mature Time Series Agents usually combine both layers, but the contribution should identify which layer is novel.

\subsection{Position relative to existing surveys}

Existing surveys cover important subsets of the landscape. LLM-for-time-series surveys emphasize serialization, prompting, reprogramming, alignment, and the limitations of LLMs as direct numerical forecasters \citep{zhang2024llmts,jiang2024empowering}. Multimodal time series surveys organize text, image, sensor, and structured temporal evidence \citep{jiang2025multimodal,liu2025crossmodality}. The survey ``From Prompts to Agents'' traces the transition from passive prompting to agentic time series analysis \citep{promptstoagents2026}. Chang et al. survey reasoning and agentic systems in time series with reasoning topologies and T-Tool/T-Agent labels \citep{changsurvey2026}. General harness surveys and Code as Agent Harness define the surrounding infrastructure that turns LLMs into stateful, executable, and verifiable agents \citep{li2026harnesssurvey,ning2026codeharness}.

Our emphasis is different. We use the harness taxonomy itself as the organizing principle, then specialize it to time series. This lets us compare TSFMs, LLM-based time series models, contextualized time-series methods, reasoning benchmarks, workflow agents, self-evolving agents, and deployment-oriented systems within a single framework. It also clarifies why forecasting alone is insufficient: forecasting is one callable capability inside a temporal analysis and decision harness.

\subsection{Contributions}

This report makes four contributions.

\begin{enumerate}
  \item It gives a precise operational definition of Time Series Agents by separating general Harness design from Time-series Harness Module design.
  \item It adapts the taxonomy of Code as Agent Harness--\hcomp{Harness Interface}, \hcomp{Harness Mechanisms}, and \hcomp{Scaling the Harness}--to temporal analysis.
  \item It provides a component-level literature map and a large harness decomposition table that identifies, for each representative work, the interface, mechanisms, scaling design, Time-series Harness Module, and contribution locus.
  \item It synthesizes benchmark and infrastructure directions, including Context-is-Key, TSRBench, TSAIA, TimeSage-MT, Dr-CiK, TimeSeriesExamAgent, HEARTS, and process-level evaluation.
\end{enumerate}

\section{Harness Vocabulary and Time-series Specialization}

\subsection{From LLMs to agents}

A standalone LLM produces text conditioned on a prompt. An agent is not only a stronger prompt. It is an LLM coupled with a harness that controls the interaction between model outputs and the external environment. Recent harness literature describes this surrounding layer as tools, APIs, sandboxes, memory, validators, state representations, permission boundaries, execution loops, and feedback channels \citep{li2026harnesssurvey,ning2026codeharness,lee2026metaharness}.

Following Code as Agent Harness, we group general Harness design into three layers \citep{ning2026codeharness}:

\begin{itemize}
  \item \hcomp{Harness Interface}: the medium through which the model reasons, acts, and represents environment state. Code-centric harnesses use executable, inspectable, and stateful artifacts such as programs, tool definitions, tests, repositories, simulators, and logs.
  \item \hcomp{Harness Mechanisms}: the operational layer that sustains the agent beyond a single generation step through \hcomp{Planning}, \hcomp{Memory and Context Engineering}, \hcomp{Tool Use}, \hcomp{Control}, and \hcomp{Harness Optimization}.
  \item \hcomp{Scaling the Harness}: the multi-agent and collaborative layer built around shared artifacts, shared execution states, structured workflows, coordination, review, and collective verification.
\end{itemize}

This taxonomy is domain-agnostic. It tells us what a harness does, but not what a time-series harness must preserve. The domain module supplies that missing specialization.

\subsection{Why time series require a Time-series Harness Module}

Time series are ordered, scale-sensitive, and context-dependent temporal objects. A Time-series Harness Module must protect at least six properties:

\begin{itemize}
  \item \keyterm{Temporal causality}: future observations, labels, and events must not leak into past decisions.
  \item \keyterm{Numerical fidelity}: temporal signals should not be reduced to lossy text serialization when precise operations are required.
  \item \keyterm{Time-indexed state}: timestamps, frequency, missingness, covariates, channels, units, and revision history must be explicit harness state.
  \item \keyterm{Temporal operation semantics}: slicing, aggregation, decomposition, smoothing, forecasting, anomaly localization, event alignment, and metric computation should be typed executable actions.
  \item \keyterm{Temporal grounding of context}: textual, visual, tabular, and event context must be grounded to intervals, lags, horizons, and causal assumptions.
  \item \keyterm{Metric-verifiable outputs}: forecasts, diagnoses, and decisions must be checked by task-specific metrics, evidence traces, and leakage-aware validation.
\end{itemize}

This is why Time Series Agents are not equivalent to prompting an LLM with a CSV. The Time-series Harness Module changes what the LLM can observe, which actions it can take, how intermediate evidence is stored, how outputs are verified, and how experience is reused.

\section{Literature Landscape}

\subsection{Temporal models as harness components}

The harness-centric view does not discard model-centric time series research. Instead, it changes its role. Classical statistical models, deep forecasters, TSFMs, LLM-based time series models, and multimodal temporal models become callable temporal tools inside the \hcomp{Time-series Harness Module} \citep{zeng2023dlinear,nie2023patchtst,wu2023timesnet,ansari2024chronos,das2024timesfm,rasul2023lagllama,woo2024moirai,goswami2024moment,timegpt2023,timer2024,jin2024timellm,unitime2024,test2024,urbangpt2024,chattime2025,timevlm2025,timeomni2026,timeomnivl2026}. They may provide forecasting, representation learning, sequence generation, multimodal understanding, or domain adaptation. They are not sufficient to define an agent, but they are important capabilities that an agent can select, execute, compare, and verify.

This distinction also helps interpret the debate on LLMs for time series. Several studies show that LLMs struggle with direct numerical forecasting or zero-shot time-series reasoning when signals are serialized as text \citep{tan2024useful,merrill2024struggle}. A domain harness reduces this burden by keeping temporal objects native, exposing operations through typed tools, and using the LLM for planning, context integration, and evidence synthesis.

\subsection{Contextualized and multimodal time series}

Contextualized time series connect numerical signals with external events, documents, images, domain descriptions, and natural-language questions. Context-is-Key (CiK) evaluates forecasting with essential textual information \citep{contextiskey2025}; Time-MQA, MTBench, MMTS-BENCH, TSAQA, TSRBench, HEARTS, and TemporalBench evaluate temporal question answering, multimodal reasoning, health-signal reasoning, and event-informed tasks \citep{timemqa2025,mtbench2025,mmtsbench2026,tsaqa2026,tsrbench2026,hearts2026,temporalbench2026}. These benchmarks motivate two domain components: temporal grounding of external context, and leakage-aware evaluation of context-conditioned reasoning.

The related work in Harnessing Generalist Agents for Contextualized Time Series is useful here because it separates three lines: time-series-only analysis, agentic time-series workflows, and contextualized/multimodal time series \citep{timeclaw2026harness}. We adopt the same separation, but reinterpret each line as part of the \hcomp{Time-series Harness Module} design space. Contextual methods contribute evidence and retrieval interfaces; TSQA benchmarks contribute validation tasks; multimodal TS methods contribute cross-modal state representations.

\subsection{Agentic systems for temporal workflows}

Early Time Series Agent work makes temporal reasoning tool-grounded. TS-Agent reasons over raw time series through iterative statistical insight gathering \citep{tsagent2025}. TimeART trains tool-augmented time-series reasoning on TimeToolBench \citep{timeart2026}. TSAG evaluates financial tool selection and faithfulness \citep{tsag2026}. FETA and ZARA use multi-agent or retrieval-augmented reasoning for training-free classification and motion time-series reasoning \citep{feta2025,zara2025}. These works primarily contribute to the harness interface and tool-use mechanisms.

Workflow agents place temporal models inside end-to-end analysis procedures. TimeSeriesScientist decomposes forecasting into curation, planning, forecasting, and reporting \citep{timeseriesscientist2025}. TimeCAP, TimeXL, FLAIRR-TS, Nexus, MoiraiAgent, TimeCopilot, and Last-Mile Forecasting Agents integrate context, retrieval, explanation, TSFMs, assistant interfaces, or forecast revision \citep{timecap2025,timexl2025,flairr2025,nexus2026,moiraiagent2026,timecopilot2026,lastmile2026}. Argos and AnomaMind extend the agentic workflow pattern to anomaly detection and diagnosis \citep{argos2025,anomamind2026}.

Multi-agent systems coordinate heterogeneous evidence or roles. TS-Debate separates numeric, visual, and textual evidence agents, while MAS4TS coordinates Analyzer, Reasoner, and Executor roles for visual time-series reasoning \citep{tsdebate2026,mas4ts2026}. These works primarily contribute to scaling the harness, but their value depends on a shared temporal evidence state.

\subsection{Adjacent LLM agents for data science}

Time Series Agents also inherit ideas from LLM agents for data science and machine-learning engineering. Data Interpreter and DS-Agent show how agents can write code, inspect intermediate outputs, reuse cases, and iterate over experiments in structured data workflows \citep{datainterpreter2025,dsagent2024}. MLAgentBench evaluates agents that modify files, run experiments, and reason over machine-learning pipelines \citep{mlagentbench2024}. These systems are not time-series agents by themselves, but they define \hcomp{general Harness} mechanisms--code execution, experiment management, stateful artifacts, and evaluation feedback--that can be specialized by a \hcomp{Time-series Harness Module}. In the proposed taxonomy, they mainly inform the general-agent layer, whereas TimeClaw-Harness, AION, MetaCaster, and TimeSeriesScientist specialize those mechanisms for temporal data.

\subsection{Self-evolving and harness-explicit systems}

The newest systems make harness components trainable or self-extending. Cast-R1 formulates forecasting as a sequential decision process with supervised and reinforcement learning \citep{castr12026}. TimeClaw with exploratory execution learning compares trajectories by metrics, distills successful experience, and reinjects it into future runs \citep{timeclaw2026explore}. KairosAgent fuses an LLM reasoner with a TSFM forecaster and uses reinforcement learning from forecasting with multi-turn refinement \citep{kairosagent2026}. MetaCaster uses a meta-harness optimized agent to synthesize few-shot training data and deploy lightweight forecasters \citep{metacaster2026}. AION formalizes realistic time-series tasks as a task-file/workspace/validation tuple and defines a practical harness with agents, skills, rules, memory, evaluation, and protocols \citep{aion2026}.

Harnessing Generalist Agents for Contextualized Time Series is particularly important because it explicitly designs a Time-series Harness Module rather than only a task-specific prompt or workflow \citep{timeclaw2026harness}. It hosts series in a task-local workspace, exposes executable temporal tools, stores episodic multimodal memory, and evolves new tools from verified trajectories. It also evaluates across CiK, TSRBench, and TSAIA, thereby connecting forecasting with contextual reasoning and financial temporal analysis.

\section{Evaluation: From Output Metrics to Harness Metrics}

Evaluating a Time Series Agent requires more than scoring the final answer. A harness-level benchmark should record the task contract, allowed context, chronological boundary, tool trace, evidence chain, final artifact, and post-hoc feedback. We distinguish four evaluation layers.

\begin{enumerate}
  \item \keyterm{Model capability benchmarks}. M4/M5, Monash, UCR/UEA, NAB, GIFT-Eval, and related suites evaluate forecasting, classification, anomaly detection, or representation transfer. They remain relevant for temporal model components inside an agent harness.
  \item \keyterm{Contextual and multimodal reasoning benchmarks}. CiK, Time-MQA, MTBench, MMTS-BENCH, TemporalBench, TSRBench, TSAQA, HEARTS, and TS-Skill evaluate whether systems can combine numerical signals with textual, visual, event, domain, or health context \citep{contextiskey2025,timemqa2025,mtbench2025,mmtsbench2026,temporalbench2026,tsrbench2026,tsaqa2026,hearts2026,tsskill2026}.
  \item \keyterm{Agent-process benchmarks}. TimeSage-MT evaluates multi-turn analytical workflows; TSAG isolates tool selection and faithfulness; TimeSeriesGym and MLAgentBench-like settings evaluate machine-learning engineering agents; TimeSeriesExamAgent evaluates benchmark generation; Dr-CiK tests active context retrieval under distractors \citep{timesagemt2026,tsag2026,timeseriesgym2025,mlagentbench2024,timeseriesexamagent2026,drcik2026}.
  \item \keyterm{Deployment and live-evaluation benchmarks}. Impermanent and live forecasting settings test temporal generalization, changing distributions, reproducibility, and operational drift \citep{impermanent2026}. Last-Mile Forecasting motivates revision-trace evaluation under business constraints \citep{lastmile2026}.
\end{enumerate}

For harness-level evaluation, the following metrics should be reported in addition to final accuracy or forecast error: tool-call validity, parameter correctness, evidence faithfulness, chronological leakage rate, context relevance, citation/distractor rate for retrieved context, calibration, uncertainty quality, latency, cost, memory contamination, regression under harness evolution, and human-review burden.

\subsection{Open problems}

\keyterm{Interface standardization.} Current systems use different tool schemas, workspaces, trace formats, and validation contracts. A Model Context Protocol-style interface for temporal tools and workspaces could make Time Series Agents comparable and composable.

\keyterm{Numerical and temporal faithfulness.} LLMs can misread scales, ignore units, hallucinate trends, or reason over future information. Typed temporal tools, unit annotations, chronological guards, and evidence-grounded generation are required.

\keyterm{Context retrieval under distractors.} Dr-CiK shows that retrieving future-relevant context is difficult when irrelevant documents are available. Temporal grounding of retrieved context and distractor-aware retrieval should become first-class benchmark dimensions.

\keyterm{Memory without leakage.} Episodic memory can improve transfer but may contaminate evaluation, encode obsolete regimes, or retrieve superficially similar but temporally irrelevant cases. Temporal memory needs provenance, expiry, family filters, and replayable audits.

\keyterm{Self-evolving harnesses without regression.} TimeClaw, MetaCaster, AION, Cast-R1, and KairosAgent suggest that tools, prompts, action-selection modules, skills, and memories can evolve. The open challenge is to verify improvement without overfitting to benchmarks or violating temporal constraints.

\keyterm{Decision-centric evaluation.} Forecasting is only one stage. Many applications require inventory decisions, trading policies, grid control, diagnosis escalation, clinical triage, or maintenance scheduling. Time Series Agent benchmarks should evaluate downstream action quality and accountability, not only predictive error.

\section{Conclusion}

Time Series Agents should be defined as LLMs coupled with both a general Harness and a Time-series Harness Module. The general Harness provides the interface, mechanisms, and scaling substrate that make an LLM into an agent. The Time-series Harness Module supplies the temporal workspace, typed operations, temporal grounding of context, leakage-aware validation, temporal memory, and domain tools required for reliable temporal analysis.

This framing absorbs previous model-centric work rather than replacing it. Classical models, deep forecasters, TSFMs, LLM-based time-series models, multimodal temporal models, and statistical procedures all become callable components inside the \hcomp{Time-series Harness Module}. The frontier is therefore shifting from standalone forecasting models to executable, verifiable, stateful, and adaptive temporal analysis systems. Future work should make its contribution locus explicit: whether it improves the general Harness, the Time-series Harness Module, or the interface between them.
