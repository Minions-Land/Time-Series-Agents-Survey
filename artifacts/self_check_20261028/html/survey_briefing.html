Survey briefing · 2026

From General to Specific

A construction-oriented survey of Time-Series Agent Systems.

The survey is a map for building the next system.

The question

Start with the developer's decision, not with a list of papers.

Given a new time-series scenario, which Agent components can be reused, which need temporal adaptation, and which must be redesigned around the task?

General capability

Interaction, memory, planning, tool use, execution, and feedback can often transfer across domains.

Temporal capability

Order, windows, units, versions, availability time, and leakage rules define what a valid operation means.

Task contract

Forecasts, diagnoses, synthetic series, and actions require different outputs, feedback, and evaluation.

Our organizing answer

Classify modules by their scope of reuse.

LLM side

How the model interprets and chooses actions

General Harness

Read the landscape

Start at the center, move outward through the three Harness layers, and read the radial sectors and outer tags as the mechanism, task, and representative-work coordinates.

One construction path

Demand forecasting is a simple running example.

01 · SCENARIO

Demand planning

Define horizon, target, covariates, and downstream inventory decision.

02 · REUSE

General runtime

Reuse tool calling, memory, planning, execution, and artifact checks.

03 · ADAPT

Temporal contract

Preserve windows, availability time, units, versions, and leakage boundaries.

04 · SPECIALIZE

Forecast procedure

Select models, revise forecasts, backtest, calibrate, and connect to action.

05 · EVALUATE

Benchmark choice

Test prediction, execution, evidence use, and inventory utility separately.

How the paper is organized

Each section answers the next construction or evaluation question.

1 · LLM-side contributions

How numerical inputs, temporal instructions, and workflow policies reach the model.

2 · General Harness

Which runtime mechanisms execute the interaction loop and preserve state.

3 · General Time-Series Harness

Which shared modules keep temporal operations meaningful and auditable.

4 · Task-Specific Harness

How output contracts determine procedures, feedback, and stopping rules.

5 · Infrastructure and Benchmarks

Which resources expose execution, evidence, temporal validity, and downstream utility.

6 · Open Problems

Where reuse, transfer, and evaluation still fail under changing information.
